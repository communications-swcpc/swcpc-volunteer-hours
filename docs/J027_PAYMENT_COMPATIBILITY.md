## Release record — November 2026 (1.0.7)

- **1.0.7 store builds:** EAS `npx eas-cli build --platform all --profile production` produced Android `8c8b5b21` (version code 19) and iOS `b562f69e` (build 17). Android went straight to the Play production track (`status=completed`, 100%, no staged rollout). iOS build 17 reached `VALID`, was submitted 2026-11-10 18:13 EST and entered review 2026-11-11 13:00 EST; release type is AFTER_APPROVAL, so it publishes itself.
- **Store listing text does not come from EAS.** Play release notes were empty after submission and had to be written separately via the Android Publisher API (open an edit, patch only that release's `releaseNotes`, commit — leaving version code and rollout alone). The App Store "What's New" is set on the version in App Store Connect. Check both after every submission.
- **New App Store Connect blocker:** Apple's age-ratings questionnaire, behind "Edit Age Ratings". A version cannot be submitted until it is answered. For this app the answers are None/No throughout — no user-generated content, no in-app purchases, no ads.
- **Reading store state without the browser:** build an ES256 JWT from `credentials/AuthKey_CQSUW98524.p8` (key id, issuer id and app id are all in `eas.json` under `submit.production.ios`) and call `GET /v1/apps/{id}/appStoreVersions`. Play state comes from the service account in `credentials/google-play-service-account.json`.
- **Tests:** 38 pass. Compile the contract and client modules with `npx tsc … --outDir <tmp>`, then run `node --test tests/*.cjs` with `HISTORY_CONTRACT_PATH`, `HISTORY_CLIENT_PATH`, `PAYMENT_CONTRACT_PATH` and `PAYMENT_CLIENT_PATH` pointing at the compiled files.
- **Before any release, check `constants/api.ts`.** `API_BASE` gets pointed at a Vercel preview during testing and must be back on `https://cms.corridorpark.org`.
- **iOS 27 SDK / UIScene — a deadline, not a bug.** Local Xcode 27.2 builds are killed at launch (SIGTRAP in `UIApplicationMain`, `…NoSceneLifecycleAdoption…`) unless the app adopts the UIScene lifecycle; a manifest entry alone is not enough, it needs a real `UIWindowSceneDelegate` that re-hosts the window. The local fix lives in `ios/`, which is gitignored and regenerated by `expo prebuild`. Builds from EAS are on the iOS 26 SDK (`DTSDKName = iphoneos26.0`) where this is only a warning, so shipped builds are fine — but **Apple requires the iOS 27 SDK from April 2027**, and Expo SDK 54 cannot do scenes. Plan the 54 → 57.0.23+/58 upgrade as its own project before then.
